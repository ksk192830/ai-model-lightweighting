# 노트북 Stage 2 TensorRT 최종 평가

## 결론

- Stage 1 통과 후보 22개가 모두 terminal 상태에 도달했다.
- 21개 후보는 엔진 생성, 엔진 검사, 3회 반복 지연시간 측정과 437장 정확도 평가를 완료했다.
- Q03은 현재 TensorRT가 INT4 block quantization `DequantizeLinear` 노드를 파싱하지 못해 엔진 생성 단계에서 종료됐다.
- 정확도 보존 gate를 통과한 비지배 후보는 **B02, B03, C01, C02, C03, C04, R01, R02**다.
- 실제 배포 균형은 C02가 가장 좋다. B01 대비 BBox AP는 +0.0022, mask AP는 -0.0003, mIoU는 +0.0292이며 중앙 지연시간은 47.1%, 엔진 크기는 49.9% 감소했다.
- R01은 정확도 gate 통과 후보 중 가장 빠른 25.82 ms(39.23 FPS)지만 반복 중앙값 CV가 5.25%로 경고 기준 5%를 소폭 넘었다.

## 평가 환경과 프로토콜

| 항목 | 값 |
|---|---|
| GPU | NVIDIA GeForce RTX 4050 Laptop GPU |
| GPU VRAM | 6,141 MiB |
| Compute capability | 8.9 |
| CUDA | 12.8 |
| TensorRT | 10.16.1.11 |
| NVIDIA driver | 580.173.02 |
| CPU | AMD Ryzen 7 7735HS, 16 logical CPUs |
| RAM / OS | 약 14 GiB / Ubuntu 22.04, kernel 6.8.0-136-generic |
| 정확도 데이터 | train/calibration과 분리된 고정 비교용 test 437장, annotation 593개 |
| 정확도 threshold | COCO AP 0.001, semantic mIoU 0.25 |
| 지연시간 | batch 1, 32장 고정 표본, warmup 20회, 측정 200회 × 3반복 |
| 측정 범위 | 메모리 내 이미지 입력부터 후처리까지, 디스크 decode 제외 |

완료 후 환경 기록 시점에는 AC 전원이 연결돼 있었고 GPU 온도는 47°C였다. 원래
지연시간 측정 중의 TGP 모드, 온도, 클럭과 백그라운드 부하는 별도로 표본화하지
않았으므로 현재 표의 지연시간은 환경 통제 전 결과다. 최종 성능 비교에는 성공한
21개 후보의 지연시간을 `power-saver`/`quiet` 전원 조건에서 전부 다시 측정한다. 새 실행기는
platform profile과 AMD P-State EPP가 각각 `quiet`와 `power`인지 먼저 확인하고 각 반복 전에 CPU/GPU 부하,
GPU 온도·전력·클럭과 AC 상태를 기록하고, 5개 연속 표본과 첫 안정 상태 기준을
통과할 때만 측정을 시작한다. 엔진 및 437장 정확도 결과는 부하 보완의 영향을 받지
않으므로 SHA-256을 재검증한 뒤 재사용한다.

## 선택 해석

| 목적 | 후보 | 근거 |
|---|---|---|
| 주 배포 후보 | C02 | 25.94 ms, 38.13 FPS, 64.8 MiB이며 세 정확도 지표가 모두 gate 통과 |
| 최고 BBox AP | B03 | BBox AP 0.7422, 26.52 ms, 68.0 MiB |
| 최저 지연시간 | R01 | 25.82 ms, 39.23 FPS; 정확도 gate 통과, 반복 변동성은 추가 확인 권장 |
| FP32 정확도 중심 | S01 | mIoU 0.7339, BBox/Mask AP 보존; 지연시간 개선은 작음 |
| Mixed precision 대안 | Q05 | 정확도 gate 통과하지만 C02보다 느리고 엔진이 큼 |

Pareto 집합의 C03, C04, R02는 일부 정확도 축에서 비지배이기 때문에 포함됐지만 B01보다 느리다. 실제 배포 후보를 고를 때는 C02, B03, R01을 우선 비교한다.

## 이 노트북에서 남은 작업

1. **전체 지연시간 절전 조건 재측정(필수):** 성공 후보 21개를 `power-saver`/`quiet` 전원 조건과 동일 부하 gate 아래 다시 측정한다. 이 결과로 현재 지연시간, FPS, 변동성 및 Pareto를 교체하며 R01 순위도 함께 재확인한다.
2. **상위 3개 성능 우선 검증:** 공식 Pareto 이후 상위 3개만 `performance` 조건에서 별도 측정하며 공식 Pareto 입력과 섞지 않는다.
3. **데이터 fingerprint 비교:** 노트북과 데스크탑의 COCO 의미 및 이미지 collection hash를 비교해 현재 정확도 결과를 재사용할 수 있는지 확정한다.
4. **논문 반영은 데스크탑에서 수행:** 이 노트북의 결과 파일을 기준으로 표·그림과 결과 장을 갱신한다. 현재 GPU에서 만든 TensorRT 엔진 자체는 다른 GPU의 성능 측정에 재사용하지 않는다.

Q03은 TensorRT 플랫폼 호환성 실패로 보고하고 Pareto에서 제외한다. 새 외부 holdout은
추가하지 않으며, 437장은 고정 반복 비교용 benchmark로만 해석하고 외적 일반화는
주장하지 않는다.

정확도와 엔진 생성까지 포함한 전체 Stage 2를 다시 실행할 필요는 없다. `--remeasure-latency` 실행으로 성공 후보 21개의 성능 측정만 교체한다.
