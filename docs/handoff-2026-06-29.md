# 작업 인수인계 — 2026-06-29

## 담당 범위

Notion의 역할 분담에 따라 이 저장소에서는 **경량화 구현**을 담당한다.
정확도·속도 평가 자동화와 논문 표·그래프 생성은 다른 담당자의 범위다.

경량화 담당 산출물은 다음과 같다.

- FP16, INT8, Pruning 변환 코드
- 평가 담당자가 실행할 수 있는 모델 파일
- 재현 가능한 실행 명령과 생성 메타데이터
- 모델 로딩 및 샘플 추론 수준의 동작 확인

## 오늘 완료한 작업

### 실행 환경과 baseline

- RF-DETR 1.8.1, PyTorch 및 torchvision 버전 고정
- front/rear checkpoint, 클래스 및 데이터 설정 파일 작성
- 환경 점검, baseline 추론 및 반복 benchmark 스크립트 작성
- raw 데이터의 인증된 Google Drive 다운로드를 `rclone` 기반으로 자동화

### 데이터 준비

- front/rear calibration 및 test 목록을 숫자 ID 기준으로 분리
- calibration과 test 사이의 중복이 없음을 확인
- Roboflow COCO Segmentation export에서 파일명 기준으로 평가 데이터 추출
- Roboflow에 없는 test 이미지는 라벨이 존재하는 가까운 ID로 교체
- 최종 labeled test: front/rear 각각 296장
- INT8 calibration: front/rear 각각 296장
- calibration 파일별 SHA-256 manifest 생성

대용량 데이터는 Git에 포함하지 않는다. 다른 컴퓨터에서는 Google Drive의
다음 폴더를 저장소 `data/` 아래에 배치한다.

```text
data/
├── calibration/
│   ├── front/
│   └── rear/
└── labeled_test/
    ├── front/
    └── rear/
```

### FP16 및 ONNX

- RF-DETR checkpoint의 ONNX export 및 ONNX checker 검증 구현
- front/rear ONNX 파일을 로컬에서 실제 생성하고 검증
- `trtexec` 기반 TensorRT FP16 engine 생성 스크립트 작성
- PyTorch FP16과 TensorRT FP16의 차이 및 실행법 문서화

TensorRT engine은 하드웨어와 TensorRT 버전에 종속되므로 Mac에서는
생성하지 않았고 최종 NVIDIA 장비에서 생성해야 한다.

### TensorRT INT8 PTQ

- front/rear calibration 이미지 296장을 사용하는 entropy calibration 구현
- RF-DETR와 같은 RGB resize 및 ImageNet normalize 전처리 적용
- INT8 미지원 레이어의 FP16 fallback 지원
- calibration cache, engine, 환경·체크섬 metadata 저장 구현
- 일괄 실행기에 `tensorrt-int8` 방식 추가

현재 entropy calibrator API는 TensorRT에서 지원되지만 deprecated 상태다.
이번 PTQ 실험에는 사용할 수 있으며, 후속 호환성이 필요하면 explicit
quantization으로 교체한다.

## 현재 생성 가능한 모델

```text
artifacts/
├── onnx/
│   ├── front/parking_front.onnx
│   └── rear/parking_rear.onnx
└── tensorrt/
    ├── front/
    │   ├── parking_front_fp16.engine
    │   ├── parking_front_int8.engine
    │   └── parking_front_int8.cache
    └── rear/
        ├── parking_rear_fp16.engine
        ├── parking_rear_int8.engine
        └── parking_rear_int8.cache
```

ONNX는 생성 완료 상태지만 `artifacts/`가 Git에서 제외되므로 다른
컴퓨터에서는 다시 export하거나 별도로 전달해야 한다. TensorRT engine은
아직 생성되지 않았다.

## 내일 바로 이어서 할 작업

### 1. Pruning 구현

가장 먼저 `Pruning 20%`, `Pruning 40%` 두 실험군을 구현한다.

- RF-DETR 구조에서 실제 제거 가능한 대상 레이어 확인
- 단순 unstructured pruning과 실제 추론 가속 가능한 structured/channel
  pruning 중 적용 방식을 결정
- 독립 실행 스크립트 `scripts/prune_model.py` 작성
- 결과 checkpoint와 pruning 비율 metadata 저장
- `scripts/run_lightweighting.py`에 pruning 방식 등록

Pruning은 0 값을 만드는 것만으로 engine 크기나 속도가 자동으로 줄지
않으므로, 구조적 제거 또는 TensorRT sparse 지원 가능성을 먼저 확인한다.

### 2. NVIDIA 장비에서 모델 생성

Google Drive 데이터를 `data/`에 받은 뒤 다음 명령으로 전체 변환한다.

```bash
python3 scripts/check_environment.py

python3 scripts/run_lightweighting.py \
  --camera all \
  --methods onnx tensorrt-fp16 tensorrt-int8
```

실행 전 점검만 하려면:

```bash
python3 scripts/run_lightweighting.py --dry-run
```

### 3. 모델 동작 확인 도구

평가지표 계산은 구현하지 않는다. 대신 경량화 담당 범위인 다음 smoke
test를 추가한다.

- TensorRT engine deserialize 성공
- 샘플 이미지 1장 추론 성공
- 출력 tensor 이름과 shape 기록
- NaN/Inf 여부 확인
- FP16/INT8 모델 파일 및 metadata 묶음 생성

### 4. 평가 담당자 전달

최종 전달 항목:

- front/rear FP16 engine
- front/rear INT8 engine 및 calibration cache
- pruning 20%/40% 모델
- 각 모델의 JSON metadata
- 실행 명령이 포함된 README
